# C Hive Sage Web 版设计规格

## 1. 目标

将现有 Power BI 右侧浮窗原型改造为独立 Web 应用，让用户无需等待 Power BI 嵌入能力即可使用指标知识问答。Web 版保留 C Hive Sage 的黑金、香槟金和暖灰视觉体系，以及报表路由、动态问题、知识依据、问题分流和反馈交互。

原 Power BI 浮窗版本保留在 `jelenajy/crm_report_ai`，Web 版代码、需求文档、变更记录和一致性检查从本版本起仅维护在 `jelenajy/crm_report_ai_web`，除非用户另行指定上传地址。

## 2. 首版范围

### 2.1 包含

- ChatGPT 式独立聊天工作台。
- 左侧导航栏和中央对话区。
- Customer Type、Product、Member Tier、Binding、NPS 报表选择。
- 报表选择驱动知识包名称、知识状态和推荐问题。
- Customer Type 现有模拟知识答案。
- Product、Member Tier、Binding、NPS 知识包待接入处理。
- 知识依据展开/收起、推荐追问和有帮助/没帮助。
- 相关但无答案、跨报表、范围外三类分流。
- 新建对话、当前会话清空和历史会话视觉占位。
- 桌面端与移动端响应式布局。
- 无外部前端依赖的本地静态服务。

### 2.2 不包含

- Power BI 报表截图或 iframe。
- Power BI 筛选条件自动同步。
- 企业登录、真实大模型、向量检索或数据库。
- 真实后台工单、反馈落库或历史会话持久化。
- Product、Member Tier、Binding、NPS 的确定性业务答案。

## 3. 页面信息架构

### 3.1 左侧导航栏

- 顶部展示 C Hive Sage 和“指标顾问”。
- 提供“新建对话”主按钮。
- 提供当前报表选择器。
- 在选择器下显示对应知识包名称与状态。
- 展示“最近对话”区域；首版为当前浏览器会话内的视觉记录，不跨刷新保存。
- 底部展示“原型演示”和知识来源说明。
- 桌面端固定显示；移动端通过菜单按钮打开为覆盖式侧栏。

### 3.2 主对话区

- 顶部栏显示当前报表名称、知识状态和移动端菜单按钮。
- 无消息时显示居中欢迎区、产品说明和“猜你想问”。
- 有消息后欢迎区收敛为普通消息流，保留报表快照。
- 消息区支持用户消息、生成中状态、结构化 AI 回答、异常提示和推荐追问。
- 底部使用 ChatGPT 式固定输入区；输入框位于居中内容容器内。

### 3.3 视觉规范

- 主色：炭黑、香槟金、暖灰和米白。
- 左侧栏使用深色背景；选中态、主要按钮和关键状态使用香槟金。
- 主内容区使用暖米白背景，回答卡使用白色与轻阴影。
- 内容最大宽度控制在 860–920px，减少超宽屏阅读负担。
- 保留 Segoe UI、苹方、微软雅黑字体栈。

## 4. 交互规则

### 4.1 报表路由

- 默认报表为 Customer Type。
- 切换报表立即更新知识包、状态和快捷问题。
- 切换不改写已生成消息；每条消息保留提问时的报表快照。
- 待接入知识包只允许知识缺失反馈，不输出确定性口径。

### 4.2 提问

- 支持快捷问题、推荐追问、发送按钮和 Enter 发送。
- Shift+Enter 换行；输入最多 500 字。
- 发送期间禁用重复提交并显示加载动画。
- 原型延续短延时模拟回答，不调用网络 API。

### 4.3 回答

- 正常回答依次展示结论、计算口径、说明、提问时所选报表、知识依据、追问和反馈。
- 知识依据默认收起，并按提问时所选报表动态命名。
- 知识缺失仅展示提交确认和模拟问题编号，不展示负责人、处理状态或响应时限。
- 跨报表问题展示目标报表推荐卡；首版只显示模拟导航提示。
- 范围外问题不创建编号，展示相关性提醒和可提问示例。

### 4.4 会话

- “新建对话”清空消息并恢复欢迎态，但保留当前报表。
- 当前会话中可记录对话标题占位；刷新后不保证保留。
- 反馈和工单均明确标注为模拟效果。

## 5. 响应式与无障碍

- 桌面端：左侧栏 260–280px，主对话区占剩余宽度。
- 小屏端：左侧栏默认隐藏，通过菜单按钮打开；遮罩或 Escape 可关闭。
- 使用语义化按钮、标签、`aria-expanded`、`aria-controls`、`aria-live` 和 `role="status"`。
- 打开移动侧栏和关闭侧栏时管理键盘焦点。

## 6. 技术实现

- 首版使用原生 HTML、CSS 和 JavaScript，无构建工具和第三方运行时依赖。
- 交付入口为 `index.html`，可通过 `python3 -m http.server` 启动本地服务。
- 知识响应与报表配置放在页面脚本中的独立配置对象，保持后续替换真实 API 的边界。
- 不嵌入旧报表 PNG，避免无关资源和大体积 Base64。
- 页面不访问外部网络资源，便于企业环境试用。

## 7. 交付文件

- `index.html`：Web 版可交互原型。
- `web版report_ai需求文档.md`：完整需求、原型边界和生产演进建议。
- `CHANGELOG.md`：按版本记录每次调整内容。
- `verify_requirements_sync.py`：校验代码交互与需求文档关键契约一致。
- `README.md`：本地启动和文件说明。

## 8. 验证标准

- 本地服务可以访问首页，所有资源返回成功。
- 桌面与移动布局均可使用。
- 五个报表均可切换，知识状态和快捷问题正确更新。
- 正常、知识缺失、跨报表和范围外问题均可演示。
- 新建对话、知识依据、推荐追问、反馈、Enter、Shift+Enter、Escape 均符合规格。
- 需求一致性脚本通过，且不存在旧产品名 `C Hive Lens` 或 Power BI 浮窗依赖。
- 新仓库提交说明包含版本号和本次变更明细。

## 9. 仓库与版本策略

- 新仓库：`git@github.com:jelenajy/crm_report_ai_web.git`。
- 初始版本：V1.0 Web。
- 原仓库不修改、不删除，作为 Power BI 浮窗方案历史版本保留。
- 后续默认提交至 `crm_report_ai_web`；只有用户明确指定其他地址时才更换目标仓库。
