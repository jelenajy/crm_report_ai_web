# Consumer Hive · C Hive Sage Web 版设计说明

版本：V1.0 Web 基线；V1.1 Premium Web UI。

详细设计决策见 `docs/superpowers/specs/2026-09-21-consumer-hive-premium-ui-design.md`。

## 1. 产品定位与品牌

本页是 Consumer Hive 的独立指标知识工作台。完整品牌层级为报表系统 `Consumer Hive`、问答产品 `C Hive Sage`、中文功能名 `指标顾问`。交互围绕选择报表、提出指标逻辑问题、查看回答依据展开。现阶段的静态页面可用于交互与设计验证；真实 AI、知识检索和后台流转尚未接入。

本仓库 `jelenajy/crm_report_ai_web` 维护 Web 版代码与文档。既有 Power BI 方案留在 `jelenajy/crm_report_ai`。Web 版没有报表截图、嵌入页面或筛选条件自动同步。

## 2. 已批准的视觉方向

- 桌面端使用深石墨左侧栏、暖象牙主内容、克制的香槟金动作和状态点。以留白、字阶和细分隔线呈现内容层级。
- 侧栏顶部为无硬框的八角北极星、`CONSUMER HIVE`、`C Hive Sage` 与 `指标顾问`。北极星的四个主尖角长于四个对角尖角，中心为深色圆核加细金描边；3.6 秒周期仅末尾短暂出现缩放、柔光环与小星芒。减少动态效果设置下呈静态标识。
- 欢迎区使用 `CONSUMER HIVE INTELLIGENCE` 眉题、`让每个指标，都有据可循。` 主标语及一行说明“请围绕所选报表询问指标逻辑；知识未收录时可在本页标记待补充。”；说明在 659px 设计视口保持单行，更窄视口可安全换行。
- 新建对话、报表触发器和输入容器采用统一的柔和圆角。输入区高度与提示字号协调，暖金圆形按钮发送。
- 不依赖外部字体、图片或前端库；页面可作为单文件离线打开。

## 3. 信息架构

左侧栏顺序为品牌、新建对话、当前报表、知识包状态、最近对话，以及底部 `Knowledge Governance / Consumer Hive · CRM Analytics / 已审核指标知识体系`。主区域顶部显示当前报表名称与知识状态；初始欢迎态显示标语和“猜你想问”；回答态显示用户问题、结构化回答与可展开知识依据。底部输入区包含多行输入、500 字计数、Enter/Shift+Enter 提示和发送按钮。

报表选项为 Customer Type、Product、Member Tier、Binding、NPS。Customer Type 的静态知识配置可返回已有口径；其他四张报表标为知识包待接入，相关问题进入知识缺失分流。切换报表会同步标题、知识包、状态、输入提示和快捷问题，历史回答仍显示提问时的报表快照。

## 4. 关键交互

### 定制报表菜单

报表选择由圆角触发器和无硬边框的深石墨 listbox 组成。菜单支持鼠标、ArrowUp/ArrowDown、Home/End、Enter/Space、Escape、Tab 和外部点击。`applyReportSelection` 是菜单与跨报表推荐卡共用的切换入口；移动端选择后关闭侧栏。菜单展开、关闭、当前选项及焦点状态与 ARIA 同步。

### 提问与回答

快捷问题、推荐追问、按钮和 Enter 可发起问题；Shift+Enter 换行，IME 组合输入期间的 Enter 不发送。500 字限制、加载期防重复提交、异常恢复及短时 Toast 沿用 V1.0 交互。回答有正常、知识缺失、跨报表、范围外四类结构。正常回答含结论、计算口径、说明、提问时所选报表、知识依据、追问与反馈。

“查看知识依据”是双向展开控件，默认收起，第二次点击收起；每条回答使用唯一依据区域 ID，按钮的 `aria-expanded`、`aria-controls`、箭头与区域 `hidden` 状态同步。依据标题始终包含提问时的报表名称，报表切换不会改写历史回答。

### 移动端

侧栏在 768px 以下变为默认关闭的覆盖式抽屉。菜单按钮打开，遮罩和 Escape 关闭；可见性、`aria-expanded`、`aria-hidden`、`inert` 与焦点恢复同步。长内容滚动时输入区维持可用。

## 5. 文案与当前技术边界

用户可见 HTML 去除“原型”“原型演示”“模拟效果”“模拟提交”“模拟导航”等内部演示措辞。用户界面强调知识范围与正式业务口径；知识缺失时标注“本页标记为待补充”，显示刷新后重置的本页临时编号，反馈 Toast 说明“本页已标记”。需求文档和 README 继续如实披露：问题编号、反馈和最近会话目前只存在于页面内，不发送到负责人，也不跨刷新保存；回答来自页面内静态配置，没有接入真实模型、知识检索、数据库或工单后台。生产化需要把这些边界替换为经认证、可审计的服务。

## 6. 交付与验证

入口为 `index.html`；以仅含公开文件的临时目录和本机回环地址启动 HTTP 服务。`verify_web_prototype.py`、`verify_requirements_sync.py`、`verify_final_review_regressions.py` 和 `verify_web_runtime.py` 分别覆盖结构、需求映射、审查回归与浏览器行为。视觉验收包含桌面、842×837、659×837 视口；服务器验收确认 `.git` 与开发文件不可访问。
