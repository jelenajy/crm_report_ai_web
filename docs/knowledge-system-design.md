# 知识系统设计与维护说明

本文件是当前 `jelenajy-doc` 实现的设计基线。仓库中早期静态原型文档记录历史方案；当描述冲突时，以本文件和当前代码为准。每次修改 Python、HTML 或验证代码，都要检查本文件的行为描述，随后运行 `python3 verify_design_sync.py --update` 刷新文件指纹，再运行完整验证。CI 对代码和本文件不同步的提交报错。指纹只检验文件是否同步更新，不能替代语义审阅。

## 组成与数据流

| 文件 | 当前职责 |
| --- | --- |
| `server.py` | 仅公开 `/`、`/index.html`、`/api/reports`、`/api/answer`。每次请求构建 `KnowledgeService`，重新读取工作簿。 |
| `knowledge_service.py` | 读取首个 XLSX 工作表、mapping、报告状态、KPI 匹配、回答边界与确定性表达。 |
| `指标别名mapping.csv` | 可维护的说法到标准指标映射，支持 `general` 和单报表作用域；服务端读取，不向网页公开。 |
| `index.html` | 五报表选择、提问、上一条问题的有限上下文、状态与回答呈现；`outputs/crm_report_ai_web/index.html` 是字节相同的交付副本。 |
| `tests/` | mapping、多文件、指标问题、回退、安全边界和 API 回归。 |
| `verify_*.py` | 页面静态契约、需求同步、最终回归、浏览器运行和本设计指纹。 |

`KNOWLEDGE_DIR` 决定服务端工作簿目录，未设置时使用应用目录。`GET /api/reports` 返回五个内部 key 对应的 `ready`、`partial` 或 `pending`。`POST /api/answer` 接受 JSON `reportKey`、`question`、可选 `previousQuestion`；问题限 1–500 字，请求体限 4096 字节，格式错误返回 400。正常响应是 `status: ok`、`scope: specialized|general`、`conclusion`；不能可靠回答时是 `status: no-answer`、`conclusion`。接口没有文档名称、引用链接或原始 DAX 字段。

## 文件格式与映射

`报表类型_知识包名称mapping.xlsx` 的首个工作表要求首行 A/B 分别为 `报表类型`、`专属知识包名称`。后续每行映射一个 XLSX 文件；`customer type` 转成内部 key `customer_type`，空格和连字符统一为下划线。相同报表重复文件名去重，顺序保留。只有页面已支持的 `customer_type`、`product`、`member_tier`、`binding`、`nps` 生效。文件名必须是当前目录下的 `.xlsx` 简单名称；路径、绝对路径和符号链接不读取。无效、缺失或无法识别结构的文件视为未加载。

专属包支持两种首表结构：

1. 客质字段表：首行 C=`字段展示名`、G=`计算逻辑`；逐行保存表头对应的**所有列**，当前完整版为 A–K：A 序号、B 分类、C 字段展示名、D Measure 名称、E 来源表名、F 来源字段名、G 计算逻辑、H 业务含义、I 技术说明、J CDS 底表逻辑、K CDS 业务逻辑。C 用于指标检索，G/H 用于有依据的定义和公式回答，I/K 用于周期及适用性约束；D/E/F/J 保留在服务端供维护及后续规则使用。若未来在 K 后增列，`fields` 也会保存对应表头列。只有 C 非空且 G/H 至少一个非空的行进入当前检索。
2. KPI 定义表：首行 A=`KPI_CN`、E=`Definition`；逐行读取 A 名称和 E 定义。

通用包固定为 `Diamond KPI Definition V2024.xlsx`：A 中文名称、B 英文别名、D 周期、E 定义。首表每行的全部实际单元格也保存在服务端 `fields`，当前回答仅依据上述已验证的语义列；空名称/定义跳过。`read_rows` 用 Python 标准库解析 OOXML shared string 和 inline string，不执行宏，也不读取其他工作表。未来结构不符的知识包必须扩展解析器、测试及本文件。

可选的 `指标别名mapping.csv` 与工作簿放在同一 `KNOWLEDGE_DIR`。UTF-8 CSV 首行固定为 `报表类型,别名,标准指标`；报表类型填 `general` 或现有内部报表 key，也接受空格形式（例如 `member tier`）。同一别名在报表专属行与通用行都存在时，当前报表行优先；同一作用域重复别名采用第一条。文件缺失或格式错误时不启用别名，不影响知识包接入状态。新增未来 KPI 的同义说法可增加 CSV 行，无须改检索代码；标准指标必须写成知识包里能匹配的名称或明确的指标族词。别名文件不通过 Web 路由提供。

## 状态和检索顺序

报表映射的文件全部有效且非空为 `ready`；部分有效为 `partial`；没有有效文件为 `pending`。这描述**报表级包接入程度**，页面分别显示“已接入”“部分知识包未接入”“知识包未接入”。一次问答采用通用口径或无法回答时，不会把已接入的报表级状态改成未接入。通用回答的消息内单独说明“此指标的专属知识未接入”，并提示核对当前报表适用性；报表已接入并不代表每个指标都完整覆盖。

检索仅有两个范围：当前报表 mapping 指定的全部专属行，然后通用包。绝不检索其他报表专属行。问题先用当前报表和通用别名表规范化（较长别名先替换），再在每个范围内查指标名完整包含、模糊名称和可解释的口径文本。两个字的短指标名只在去掉“如何/定义/是什么/周期”等问法后仍与完整问题相等时命中，避免“新客第二次购买”误答成“新客”。多个无从判定的指标名同时出现则不选单一专属定义。模糊名称评分只针对含有至少 3 字连续共同 KPI 片段的候选：在问题中滑动长度接近指标名的文字窗口，取最高 `SequenceMatcher` 相似度占 70%，最长共同片段长度占 30%；阈值 0.72，前两候选差小于 0.06 时不决定。通用包采用同一阈值，近似同分而名称不同则弃权。口径文本匹配先把“除以”“÷”“／”统一为 `/`，再要求连续共同片段至少 6 字、覆盖可解释说明/定义的 80%，且领先下一候选至少 0.1；含原始 DAX 的文本不参与。专属 G 列若是简单 `DIVIDE(分子, 分母)`，可解析成可读公式并在公式反查、关系分析中使用；不带年份的反查排除“去年”“同比”行，避免同式不同周期的歧义。当问题在问“哪个指标对应这个公式”时，优先用口径文本反查，找不到完整公式时不把“订单数”“客数”等组成项当作答案。重复周期行由问题中的 MTD/YTD/R12 选择，无法缩到单行时不提供单一定义。专属 G 的简单 DIVIDE、文字比率、差值或简单 SUM 可转成可读口径；H 给出业务含义；I 给出经规则识别的周期/差值提示。复杂 DAX、J 列 SQL 和 K 列原始逻辑均不直接返回。新客二回率没有指定 C2B/C2C 时，会展示今年两种专属口径及其适用周期；若用户问 MTD 且 I 只标 YTD/R12，则不给出直接 MTD 公式，K 明示需通过 YTD 推导时可提示该限制。`新客二回` 的宽泛定义使用通用包的全渠道 YTD/R12 与 MTD 两行说明差异，并提示补充维度。简短的 `YTD 新客二回`、`MTD 新客二回` 或 `R12 新客二回` 若未指定维度，则分别以通用包的全渠道人数口径作有边界的示例，同时提醒 BA、柜台、单渠道有各自口径；含“率”或“基数”的提问不走人数概览。

“多少个/几个/哪些/列出/分别是什么……跟 X 相关的 KPI”是**报表清单问题**。系统从“跟/与/和/关于……相关”或“X 相关”提取主题 X；“共有/总共/一共/所有 KPI”则统计全表。在当前报表所有映射包完整加载时，以专属指标名称包含 X 的去重集合回答数量。全表只问数量时仅返回去重条目数；需要列出名称时最多给前 10 个，更多时明确标记省略。此类问题不会以通用包数量冒充当前报表数量；缺主题、未命中或包不完整时说明无法可靠统计。预测、原因、趋势、真实数值等缺少数据的请求直接弃权。上一条问题仅用于“新客二回”到“二回定义”的有限追问，不保存或推断更长会话历史。

本版没有外部模型、向量数据库或开放式语义推理。较自然的回答来自问题类型识别、已加载行的去重统计、有限的公式推导、维度/周期提示和页面对话措辞；任何新事实都必须可追溯到已加载字段或上述显式规则。不要把界面文案描述成模型推理。

在清单和定义之外，`_reasoned_answer` 还处理知识口径能够支持的分析问题。`plain_ratio` 只提取无 DAX、恰有一个 `/` 的文字公式；`divide_parts` 只解析简单 DIVIDE。对于比率上涨或下降，它说明分子相对分母的变化方向，并明确具体原因需要实际数据；对于“关系”，它识别已知分子/分母，或从同一报表的两个比率中约去共同项，推得组合比率。无年份问句不会取“去年”的专属比率作为默认值；当专属口径无法唯一对应问题时，可依据通用公式回答并标记通用范围。跨今年/去年的两个比率不会被直接组合。对于“区别”，可并列比较两个比率的分子/分母；新客二回 MTD 与 YTD/R12 使用通用包两行口径比较。若只有指标名但没有可解释公式，不会推断数字、因果或业务关系。组合推导要求相同周期和客群、分母非零。

## 页面与安全边界

页面通过 `escapeHtml` 呈现 API 文本，保留提问时所选报表快照。通用回答提示其适用性待报表负责人确认。服务端 GET 路由是白名单，直接请求 XLSX、README、隐藏文件或目录返回 404；网页和 API 不提供文件名、原始表格、DAX 或知识依据展开。此保护仅限制 Web 服务输出：仓库已上传的原始 Excel 可被有仓库权限的人取得，反复提问也可逐步收集回答。正式部署应把包移到私有存储，配置登录、报表权限与访问审计。

## 维护步骤

1. 在 `KNOWLEDGE_DIR` 放入符合现有结构的 XLSX，在 mapping 增加报表类型和文件名。一个报表多个包就增加多行。需要支持不同叫法时，同目录维护 `指标别名mapping.csv` 的报表类型、别名、标准指标。更新文件后，API 下一次请求加载新内容。
2. 检查 `/api/reports` 的状态，提问具体指标与相关 KPI 数量，验证专属优先、通用回退、缺包提示、无法回答和不泄露源文件。新报表选项需同时扩展服务端 `REPORT_KEYS` 与页面配置。
3. 若修改代码，同步更新本文件的职责、规则或限制，执行 `python3 verify_design_sync.py --update`，审阅指纹变动并运行 README 的验证命令。`index.html` 与输出副本必须保持字节一致。
